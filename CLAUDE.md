This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Raluca-Maria Sandu's personal portfolio/blog site: a Flask app that renders Jinja templates + Markdown content, frozen into static HTML via `frozen-flask` and deployed to GitHub Pages. There is no client-side JS framework — Bulma (SCSS) for styling plus a small `bulma.js` for the navbar burger menu.

## Commands

Python deps are managed with `uv` (there's a `uv.lock`), but `requirements.txt` is what CI actually installs from.

```bash
# Setup
uv sync                    # or: pip install -r requirements.txt

# Run the dev server (Flask debug mode, http://localhost:5000)
python main.py

# Run tests
pytest
pytest tests/test_app.py::test_publications_flow   # single test

# Build the static site (frozen-flask) into src/build/
python freeze.py

# Compile SCSS -> src/static/css/main.css (Bulma)
npm install
npm run build-bulma        # one-shot compile
npm start                  # watch mode
```

CI (`.github/workflows/deploy.yml`) installs `requirements.txt` and runs `python freeze.py` on every push to `main`, publishing `src/build` to GitHub Pages. There is no CI step that runs `pytest` or rebuilds SCSS — run both locally before pushing if templates, `src/app.py`, or `custom-styles.scss` changed.

## Architecture

- **`src/app.py`** is the whole application: Flask routes, YAML/Markdown loading, and blog post parsing all live here. Routes: `/`, `/publications.html`, `/blogList.html`, `/search/blogList/<tag>.html`, `/blog/<page_name>.html`.
- **Content sources**:
  - `src/data/*.yaml` — structured data (`home.yaml`, `publications.yaml`, `timeline.yaml`) rendered into the home and publications pages.
  - `src/templates/pages/blog/*.md` — blog posts with YAML frontmatter (`title`, `subtitle`, `date`, `cover-img`, `thumbnail-img`, `tags`), parsed with `python-frontmatter` and rendered with `markdown`. `template.md.template` is the scaffold for new posts (not picked up as a post — only `.md` files are).
  - `src/markdown_extensions.py` — `BulmaImageExtension`/`BulmaImageProcessor` rewrites Markdown image syntax into `<figure class="image"><img class="blog-image" src="{{ url_for('static', ...) }}">`, so image paths in post Markdown are relative to `src/static/` (e.g. `img/example.png`).
  - Blog post ordering everywhere (index, blog list, tag search) is by `date` descending, computed in `list_all_blog_info()`.
- **Templates** (`src/templates/`): `base.jinja` is the shared shell (nav, footer, fonts, meta description block); `pages/*.html` extend it; `blog.jinja` is the single template used for every blog post; `partials/` holds shared includes like the footer.
- **Static build output**: `src/build/` is generated by `freeze.py` — treat it as build output, not source. It mirrors `src/static/` plus the frozen HTML pages. Don't hand-edit files under `src/build/`.
- **`freeze.py`** registers URL generators for the dynamic routes (`render_blog_page`, `search_tag`) so Frozen-Flask knows every `<page_name>` and `<tag>` value to bake into static pages — when adding a new dynamic route, it needs a matching generator here or the freeze step won't emit pages for it.
- Tests (`tests/test_app.py`) cover the YAML/Markdown loading pipeline, route rendering (via `app.test_client()`), the Bulma image processor, and a full `Freezer` dry-run against a temp directory — good reference for how routes and content loading are expected to behave.

## Adding a blog post

Copy `src/templates/pages/blog/template.md.template` to a new `YYYY-MM-DD-slug.md` in the same directory, fill in frontmatter, and reference images with paths relative to `src/static/` (e.g. `img/foo.png`) — the `BulmaImageExtension` resolves them via `url_for('static', ...)`.
